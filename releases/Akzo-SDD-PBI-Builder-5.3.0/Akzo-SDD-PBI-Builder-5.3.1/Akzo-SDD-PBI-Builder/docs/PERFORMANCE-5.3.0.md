# Performance measurements: 5.2.2 versus 5.3.0

Generated by maintainer/benchmark-530.cjs on 2026-11-01 (AMD Ryzen 7 PRO 4750U with Radeon Graphics, Node v26.5.1, win32). Median of 3 runs for time; counts come from instrumenting the file handles, identically for both versions (the frozen 5.2.2 core is maintainer/fixtures/baseline-v5.2.2-core.cjs). Counts are reproducible; times are not.

## Source discovery on a synthetic workspace (150 projects of about 4 KiB each, one solution, 1800 source files)

Each cell is 5.2.2 → 5.3.0. File opens include existence and size checks; bytes are file body bytes actually read; writes are file writes.

| Run | File opens | Bytes read | Writes | Bytes written | Time (ms) |
| --- | ---: | ---: | ---: | ---: | ---: |
| first run | 152 → 152 | 677,290 → 677,290 | 2 → 3 | 71,070 → 116,378 | 490.5 → 446.1 |
| rerun, nothing changed | 152 → 156 | 677,290 → 62,743 | 2 → 0 | 71,070 → 0 | 417.0 → 414.7 |
| rerun, 3 projects edited | 152 → 156 | 677,329 → 92,612 | 2 → 1 | 71,070 → 62,722 | 407.2 → 399.9 |

The directory walk still lists every non-excluded entry on every run: a browser cannot know which folders changed without listing them. What 5.3.0 removes is rereading and reparsing unchanged solutions and projects, and rewriting an identical map. On a repository with small project files the previous map costs about as many bytes as it saves; the saving grows with project file size and count.

## Approve & Generate on a CDMS + DAB + UI PBI (7 evidence sources, 3 documents × 3 formats)

| Version | File opens | Opens of an already opened file | Bytes read | Writes | Time (ms) |
| --- | ---: | ---: | ---: | ---: | ---: |
| 5.2.2 | 94 | 73 | 214,992 | 13 | 330.8 |
| 5.3.0 | 94 | 73 | 214,992 | 13 | 353.4 |

Approve & Generate rereads working documents and evidence several times on purpose: each pass is an integrity check (review snapshot, content scan, post-write verification, final readiness check) that protects the approval from concurrent edits. 5.3.0 did not weaken or remove any of them, so this count is expected to be unchanged.

## Agent instruction size (characters loaded into every conversation, then guides loaded lazily when their step starts)

| Version | Agent file | Guide files | Guide characters (loaded only when needed) |
| --- | ---: | ---: | ---: |
| 5.2.2 | 36,470 | 9 | 74,436 |
| 5.3.0 | 41,232 | 9 | 76,289 |

The 5.3.0 agent file is larger by 4,762 characters: the compact workflow router, the minimum-sufficient-evidence policy and the shared-UI and difference-map rules replaced the earlier guide list but added new rules. Token cost is not claimed to fall; guides still load only when a step needs them.

## Not measured here
Model tokens, tool calls, wall-clock time of a real refinement and the quality of Copilot answers happen inside the chat host. The page reports file opens, bytes, writes and elapsed time through Run details; the agent records the rest in EVIDENCE.md "Run metrics" when its host exposes them.
